Our `delay()` function is a **busy-wait polling** function that completely stops the CPU from doing any other work than counting. 

- It's like counting how many seconds until sun rise so you don't wake up late

- This is brain dead. We should implement some sort of alarms so we can do something else in the mean time

- What should this alarm have? Well, something to make noise (clock hardware), someone to hear the alarm (the human ear)

&nbsp;

Thankfully, microcontrollers have some built-in alarms called **interrupts**. One of these interrupts is named `SysTick`: 

- It holds a value and decrements by 1 per CPU clock cycle. When the counter reaches 0, it sends an interrupt signal to the CPU

- Then the value reloads back up, and starts decrementing again

- The interval between each interrupts is specified in the `SysTick->LOAD` register

Of course, the CPU samples the status of the interrupt line before each instruction. As long as the line stays low, the CPU will fetch the next instruction from the pipeline. However, when the line is high, the CPU will execute the `Interrupt Entry` instruction. This process is called **preemption** and will be discussed more in the next video.

With these information, we're ready to use the system interrupt instead of the hard coded `delay()` function.

&nbsp;

## Replacing `delay()`


```c
#include "tm4c_cmsis.h"

#define SYS_CLOCK_HZ 16000000U

/* interrupts the CPU every 0.5s */
SysTick->LOAD = SYS_CLOCK_HZ/2U - 1U; // -1 since it's counting from 0
SysTick->VAL  = 0;
SysTick->CTRL = (1U<<2) | (1U<<1) | 1U; // turn on bits 2, 1, 0 to configure SysTick
__enable_interrpt();
```

The `SysTick->CTRL` modifications allows the exception `SysTick_Handler()` to be raised each time `SysTick->VAL` reaches 0. The exception already exists, but we can overwrite it to change its behaviour:

```c
void SysTick_Handler(){
    GPIOF->DATA_Bits[LED_RED] ^= LED_RED; // XOR to toggle red LED
}
```
