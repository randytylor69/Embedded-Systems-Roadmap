### 2. Reading the Data Sheet

Going a level lower, to make the LED blink, a memory map is required to see all the continents and islands of the address space - such as the RAM island. Luckily, someone already mapped it out inside the [data sheet](https://www.ti.com/lit/ds/symlink/tm4c123gh6pm.pdf) for the specific board we're using, which is merely *1,400* pages long.

The beginning of the memory map of our micro-controller looks like this:

<img width="915" height="446" alt="image" src="https://github.com/user-attachments/assets/d13e1a3f-f255-4066-b38f-47b5c28f7eaa" />

&nbsp;

For example, the first island on this map, called **on-chip flash**, exists between the addresses `0000 0000` to `0003 FFFF`. Remember that we're looking for the **GPIO-F** island; and surely enough, it's right here between the address `4002 5000` to `4002 5FFF`:

<img width="1240" height="464" alt="image" src="https://github.com/user-attachments/assets/afad8822-6295-418e-abe4-2fb26feed7d9" />

&nbsp;

However, if we search for address `0x40025000` on Keil's memory window, the values appear to be empty (`---- ----` or `???? ????`). This is a common practice known as [clock gating](https://en.wikipedia.org/wiki/Clock_gating) that blocks certain parts of the hardware to save power, so we need to manually turn the port on. 

Inside the data sheet, search for **clock gating**, go to the first page of its occurrence, then search for **GPIO**. Surely enough, the detailed description of the **GPIO Clock Gating Control Register** shows up! 

<img width="1037" height="303" alt="image" src="https://github.com/user-attachments/assets/cf93c762-ce85-4c28-8e59-fc90e89ff003" />

&nbsp;

This is a very typical format commonly used in data sheets:

- The register is shown as a block of bits
- The type of each bit is indicated: `RO` means **Read Only**, `RW` means **Read Write**, `WO` means **Write Only**
- Special bits' roles are documented in detail

By reading the description on bit `5` of the GPIO register, we discover its role:

| Value | Description |
| :-- | :-- |
| 1 | Enable and provide and clock to GPIO Port F in Run mode |
| 0 | Disable the GPIO Port F | 

This confirms that this register is the one we're looking for! Let's add the offset value `0x608` to its address `0x400FE000` to get `400F E608`, which is the location of the register in memory. 

&nbsp;

### 3. The Code

```C
int main(){
	*((unsigned int *)0x400FE608U) = 0x20U; // enable bit 5 on GPIOCGCR
	*((unsigned int *)0x40025400U) = 0x0EU; // enable bits 1,2,3 on GPIODIR
	*((unsigned int *)0x4002551CU) = 0x0EU; // enable bits 1,2,3 on GPIODEN
	
	while(1){
    /* insert whatever delay function */
		*((unsigned int *)0x400253FCU) = 0x02U;
    /* insert another delay function */
		*((unsigned int *)0x400253FCU) = 0x00U;
	}
	
	return 0;
}
```

&nbsp;

Before we start, note that everything above is **unsigned**. This is good practice so the compiler doesn't misunderstand some digits to be a signed bit and ruining the code.

First, as explained earlier, we should enable the **GPIO Clock Gating register** on `0x400FE608` by setting bit 5 to `1`. In hexadecimal, this becomes `0x20` (`0000 0020`). 

- Note that **bit 5** is NOT **decimal 5**! Bit 5 is `2^5` = `32` in decimal, which translates to `0x20` in hex

Then, we should set bits 1, 2 and 3 to `1` inside the **GPIO Pin Direction register**. 

- Note that by enabling bits 1, 2 and 3 to `1`, we obtain the decimal value $2^1 + 2^2 + 2^3 = 14$, which is `0xE` in hex

Finally, we set the same bits to `1` inside the **GPIO Digital Function register**. Don't worry about what the last 2 registers do; they'll be covered in later lessons. But do know how turning on certain bits result in certain hex values.

#### The While Loop

Now that everything's correctly configured, we can finally blink some lights. It's actually rather simple: we just need to set bit 1 of the **GPIO F Data register** to turn on the Red light; then set the bit to 0 to turn it off.
