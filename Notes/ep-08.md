> The C stack is one of the most wide used C concepts, powering functions, interrupt, context switch and *RTOS*

Guess what? We can further optimize our blinky code by creating reusable functions:

```c
void delay(){
    int volatile counter = 0;
    while (counter < 50000) counter++;
}
```

How does Assembly handles the above C function?

&nbsp;

### R14 (LR - Link Register)
In Assembly, the `delay()` function is translated to the `BL` instruction (Branch with Link), that saves the address of the next instruction into the R14 register (the Link Register). This way, the LR remembers the address that the program returns to after `delay()` finishes executing.

### R13 (SP - Stack Pointer)
The `delay()` function begins by adjusting the `SP` register (`SUB   SP,SP,#0x4`). A C stack is just an area in memory that grows/shrinks from one end. The end is called the "top" of the stack, and `SP` contains its address. 

- The stack grows towards lower memory addresses, which is "up" in the memory view
- The stack shrinks towards higher memory addresses, which is "down" in the memory view

Now the `SUB` instruction makes sense: it subtracts `#0x4` from `SP` and "grows it" by 4 bytes, allocating enough space for our `counter` variable. By the end of `delay()`, we surely see the `ADD SP,SP,#0x4` instruction that shrinks `SP` by 4 bytes.
