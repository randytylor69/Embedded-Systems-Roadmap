> But what if there's an even more dynamic way of modifying the bits - such as atomically changing individual bits of the GPIO register as we wish, from any part of our code, including from **interrupt**

Recall from the last episode that for the C instruction:

- `GPIO_PORTF_DATA_R |= LED_RED`

The Aseembly code becomes:

```asm
LDR     ; read and load register
ORR     ; perform bit-wise OR
STR     ; write to register
```

Instead of performing 3 operations, we could concatenate them into 1 write operation using Arrays. This allows us to manipulate each GPIO bit independently without having to worry about accidentally modifying other bits. You can already see where this is going if you know how arrays work in C.

## Arrays

Array is a data type that holds items of the same type and are positioned consecutively in memory. You already know this, so we jump ahead a bit.

Every register is a pointer, which in turn is an array. We can use this to our advantage to turn on the red LED without using bit operations:

```c
#define LED_RED (1U << 1) // 0x1 left-shift becomes 0x2

GPIO_PORTF_DATA_BITS_R[LED_RED] = LED_RED; // turns on the red LED
GPIO_PORTF_DATA_BITS_R[LED_RED] = 0; // turns off the red LED

```

The index and the value are the same variable, but they serve completely different purposes:

- The index `[LED_RED]` accesses R[2], which is the 3rd bit that controls Pin 1 (the Red LED). It tells the hardware that only this pin is allowed to change. 

- The value `LED_RED` turns on the 1st pin at `0x02`. 

I know this is kinda confusing but when you really think about it, it works.
