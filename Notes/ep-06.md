Suppose we modify the program a bit:

- The Blue LED is turned on
- Then, the Red LED starts blinking, while the Blue LED stays no

A problem arises: with our previous knowledge, to turn on the Blue LED would require:

```c
GPIO_PORTF_DATA_R = 0x04U; // 0x4 hex = bit 2 = pin 2 = blue light
```

Then to turn on/off the Red LED:

```c
GPIO_PORTF_DATA_R = 0x02U; // 0x2 hex = bit 1 = pin 1 = red light
```

But the 2nd operation overwrites the 1st operation! This is where bit-wise operations come in handy.

## Bit-wise Operations in C

| Operation | Symbol | Description | 4-Bit Example | Result |
|:---|:---:|:---|:---:|:---:|
| **AND** | `&` | `1` only if both bits are `1` | `1100 & 1010` | `1000` |
| **OR** | `\|` | `1` if at least one bit is `1` | `1100 \| 1010` | `1110` |
| **EOR** | `^` | `1` if bits are different (Exclusive OR) | `1100 ^ 1010` | `0110` |
| **NOT** | `~` | Inverts every bit (`0` -> `1`, `1` -> `0`) | `~1100` | `0011` |
| **LEFTSHIFT** | `<<` | Shifts bits left by $n$ positions, filling with `0` on the right | `0011 << 2` | `1100` |
| **RIGHTSHIFT** | `>>` | Shifts bits right by $n$ positions, discarding shifted-out bits | `1100 >> 2` | `0011` |

As an embedded systems programmer, we must know the bit-wise operators in-n-out. In fact, we should use it right away in our blinky program to help resolve the previous prblem:

```c
#define LED_RED    (1U << 1)
#define LED_BLUE   (1U << 2)
#define LED_GREEN  (1U << 3)

/* ... some code */
GPIO_PORTF_DATA_R = LED_BLUE;

while (1){
    GPIO_PORTF_DATA_R |= LED_RED; // OR'ing the two to turn on both!
    GPIO_PORTF_DATA_R &= ~LED_RED; // turn off red
}
```

Going into disassembly, we see the compiler allocating similar Assembly code for the 2 operations:

| C | Assembly | Notes
|--- | --- | --- |
| `...\|= LED_RED` | `LDR` -> `ORR` -> `STR` |  |
| `...&= ~LED_RED` | `LDR` -> `BIC` -> `STR` | `BIC` is "Bit Clear" |

This is quite remarkable, because the compiler didn't exactly follow our instructions for the 2nd operation (bit-wise `AND` followed by compliment bit mask), instead it generated a better `BIC` instruction (which does the same thing but more efficienct).
